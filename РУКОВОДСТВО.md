# FABULA ONE — полное руководство по логике проекта

Документ для владельца сайта (Дмитрий). Объясняет **как всё работает под капотом** и **что делать в конкретных ситуациях**. Технические детали приведены так, чтобы по ним мог сориентироваться и не-программист, и разработчик.

Слоган проекта: «Звук глубже слов». Продукт — продажа цифровых аудиофабул + персональные фабулы на заказ.

---

## 1. Из чего собран проект

Один сайт = одно приложение. Витрина и админка живут в **одном** процессе Next.js, поэтому отдельный «бэкенд» поднимать не нужно.

| Слой | Технология | Зачем |
|------|-----------|-------|
| Сайт + API | Next.js 15 (React 19) | Всё, что видит покупатель, и все `/api/*` |
| Админка / CMS | Payload CMS 3 | Управление товарами, заказами, партнёрами и т.д. |
| База данных | PostgreSQL 16 | Хранит всё: заказы, клиентов, продукты |
| Очередь | Redis 7 | Задел под авто-обработку PERSONAL (пока «спит») |
| Хранилище аудио | Yandex Object Storage (S3) | Приватный бакет для платных треков |
| Платежи | ЮKassa | Карты + СБП, чеки по 54-ФЗ, возвраты |
| Почта | SMTP (Unisender и т.п.) | Письма покупателям и вам |
| Аналитика | Яндекс Метрика | Трафик + цель «покупка» |

Всё это запускается через Docker Compose (контейнеры `app`, `postgres`, `redis`, `nginx`).

### Карта адресов

- **Публичные страницы:** `/` (витрина), `/product/<slug>` (фабула), `/checkout`, `/success`, `/personal`, `/personal/questionnaire`, `/pages/<slug>` (юр. тексты).
- **Личный кабинет покупателя:** `/auth/login` → `/cabinet` (вход без пароля).
- **Партнёрский кабинет:** `/partner/login` → `/partner/cabinet`.
- **Админка:** `/admin`.
- **Служебное:** `/api/health` (проверка, что сервер жив), `/robots.txt`, `/sitemap.xml`.

## 2. Админка — ваш пульт управления

- Адрес: `https://fabulaone.ru/admin` (локально `http://localhost:3000/admin`).
- **Первый вход:** при первом открытии `/admin` система попросит создать аккаунт администратора — задаёте почту и пароль сами. Это и есть ваш вход.
- Роль в системе одна — **Администратор**. Покупатели и партнёры в админку не заходят: у них свои кабинеты на сайте.

Разделы админки сгруппированы:

- **Каталог** — «Продукты» (фабулы) и «Полные треки» (платные аудиофайлы).
- **Продажи** — «Заказы» и «Промокоды».
- **PERSONAL** — «Персональные заказы» и «Анкеты».
- **Партнёры** — «Партнёры» и «Начисления».
- **Клиенты** — покупатели.
- **Контент** — юридические и информационные страницы.
- **Система** — «Медиа» (картинки/обложки) и «Пользователи» (админы).

## 3. Что где хранится (справочник данных)

Каждая «коллекция» — это таблица в базе. Кто её заполняет:

| Коллекция | Что хранит | Кто пишет |
|-----------|-----------|-----------|
| **Продукты** | Фабулы: название, slug, цена, обложка, демо, полный трек | Вы вручную |
| **Полные треки** | Платные аудиофайлы (приватные) | Вы загрузкой |
| **Медиа** | Обложки, картинки, OG-превью | Вы загрузкой |
| **Заказы** | Обычные покупки, статус, оплата, партнёр, промокод, UTM | Система при чекауте |
| **Персональные заказы** | Заказы PERSONAL, анкета, готовый файл | Система + вы (файл) |
| **Клиенты** | Email/имя покупателей, согласия на ПД | Система при покупке |
| **Партнёры** | Реф-код, %, баланс, статистика | Вы (кроме баланса) |
| **Начисления** | По одному на каждый оплаченный заказ партнёра | Только система |
| **Промокоды** | Код, тип и размер скидки, лимиты | Вы вручную |
| **Анкеты** | Конструктор полей анкеты PERSONAL | Вы вручную |
| **Страницы** | Оферта, политика и т.п. | Вы вручную |
| **Пользователи** | Администраторы | Вы |

> Поля «баланс», «начислено», «использований», «переходов» помечены «только чтение» — их считает система, руками не трогайте.

## 4. Как работает покупка фабулы (главный поток)

Это ядро проекта. Регистрация покупателю не нужна — только email.

1. **Выбор.** Покупатель на `/product/<slug>` слушает демо и жмёт «Купить» → попадает на `/checkout`.
2. **Оформление.** Вводит email (имя/телефон по желанию), при желании промокод, ставит две галочки — **оферта** и **согласие на обработку ПД**. Без обеих галочек заказ не создастся.
3. **Создание заказа** (`POST /api/checkout`). Сервер:
   - проверяет, что продукт существует и опубликован;
   - если есть промокод — проверяет его и считает итоговую цену;
   - находит или создаёт «Клиента» по email (записывает согласие + IP);
   - смотрит партнёрскую cookie `fabula_ref` — если есть, привязывает партнёра к заказу;
   - создаёт «Заказ» в статусе **Ожидает оплаты** с номером вида `FO-<время>`.
4. **Платёж ЮKassa.** Сервер создаёт платёж и возвращает ссылку на оплату; покупателя перекидывает на страницу ЮKassa (карта или СБП). В платёж уходит **чек по 54-ФЗ** (позиция «услуга», НДС не облагается).
5. **Подтверждение оплаты.** ЮKassa присылает **webhook** на `POST /api/webhooks/yookassa`. Сервер **не верит письму на слово** — заново запрашивает платёж у ЮKassa, сверяет сумму и статус. При совпадении:
   - заказ → статус **Оплачен**, фиксируется способ оплаты и дата;
   - +1 к счётчику промокода (если был);
   - если есть партнёр — создаётся «Начисление» и растёт его баланс;
   - генерируется **подписанная ссылка** на скачивание (живёт 1 час);
   - уходят письма (см. ниже).
6. **Письма покупателю:** (1) «Оплата прошла» со ссылкой на скачивание + (2) «Ссылка входа» в личный кабинет. Вам приходит письмо «Новый заказ».
7. **Доступ.** Покупатель качает файл из письма или заходит в `/cabinet` (по ссылке входа) и качает оттуда в любой момент — там ссылка генерируется заново при каждом заходе.

### Подстраховка, если webhook опоздал
Пока покупатель на странице `/success`, в фоне работает автопроверка (`PaymentSync` → `POST /api/payments/sync`): она сама переспрашивает ЮKassa о статусе (до 15 попыток) и, если оплата прошла, доводит заказ до «Оплачен» и шлёт те же письма. То есть доступ выдаётся, даже если webhook по какой-то причине не дошёл.

### Защита от повторов (идемпотентность)
- Ключ платежа в ЮKassa = ID заказа, поэтому двойной клик «Оплатить» не создаёт два платежа.
- И webhook, и автопроверка проверяют «заказ уже оплачен?» — повторные уведомления не начисляют партнёру дважды и не шлют письма второй раз.
- Сумма всегда сверяется: если она не совпала с заказом, доступ **не** выдаётся (запись в лог).

## 5. FABULA ONE PERSONAL (персональная фабула на заказ)

Отдельный поток с фиксированной ценой (`PERSONAL_PRICE`, по умолчанию 9 900 ₽). Здесь после оплаты человек заполняет анкету, вы делаете файл вручную и отдаёте его.

Статусы персонального заказа и что они значат:

1. **Ожидает оплаты** — заказ создан (`POST /api/checkout/personal`), клиент ушёл платить.
2. **Оплачен, ожидает анкеты** — оплата подтверждена (webhook/автопроверка). Клиенту уходит письмо со ссылкой на анкету, вам — «Новый заказ (PERSONAL)».
3. **Анкета заполнена** — клиент отправил ответы (`POST /api/personal/questionnaire`). Ответы видны в заказе в поле «Ответы на анкету».
4. **В работе** — этот статус ставите **вы** руками, когда взяли заказ в производство (для себя).
5. **Готово** — вы поставили этот статус. Триггер: клиенту автоматически уходит письмо «Ваша фабула готова», и (задел на будущее) ставится задача в очередь Redis.

**Что делаете вы:** дождаться статуса «Анкета заполнена» → прочитать ответы → создать аудио → загрузить его в бакет и вписать путь в поле **«Ключ готового аудиофайла»** (`audioKey`, например `audio/personal-FP-123.m4a`) → сменить статус на **Готово**.

Анкета настраивается в разделе **PERSONAL → Анкеты**: вы сами задаёте поля (текст, длинный текст, выбор одного/нескольких вариантов), обязательность и порядок. Активная анкета одна.

## 6. Личный кабинет покупателя (вход без пароля / magic link)

Паролей у покупателей нет. Вход — по одноразовой ссылке из письма.

- **Как получают ссылку:** либо автоматически после покупки (письмо «Ссылка входа»), либо сами запрашивают на `/auth/login`, введя email.
- **Что происходит:** ссылка содержит подписанный токен (живёт **24 часа**). Переход по ней (`/auth/magic`) проверяет токен и ставит cookie-сессию на **30 дней** — дальше кабинет открывается без писем.
- **Безопасность:** если ввести email, которого нет в базе, система всё равно ответит «ок» и не выдаст, есть такой клиент или нет (защита от перебора почт).
- **Что показывает `/cabinet`:** список **оплаченных** обычных заказов этого email с кнопкой «Скачать» (ссылка на файл генерируется заново при каждом заходе, живёт 1 час).

> Важно: в кабинете показываются **обычные** заказы. Персональные заказы в списке кабинета не отображаются — их файл отдаёт письмо о готовности и отдельный маршрут (см. §13, п. 4).

## 7. Партнёрская программа

Партнёр приводит покупателей по своей ссылке и получает процент.

- **Ссылка партнёра:** `https://fabulaone.ru/?ref=КОД`. Когда человек по ней заходит, сайт кладёт cookie `fabula_ref` на **30 дней** (настраивается `AFFILIATE_WINDOW_DAYS`).
- **Атрибуция:** если покупка происходит в течение этих 30 дней, заказ привязывается к партнёру. Партнёра также можно «зашить» в промокод — тогда покупка с этим промокодом засчитывается партнёру, даже без ссылки.
- **Начисление:** только **после подтверждённой оплаты**. Создаётся запись «Начисление» = сумма заказа × процент партнёра, и растут его «баланс», «начислено», «оплаченных заказов», «сумма продаж».
- **Кабинет партнёра:** `/partner/login` → `/partner/cabinet`. Вход по **email + паролю** (у партнёра свой). Внутри — баланс, статистика и история начислений.
- **Процент** у каждого партнёра свой (поле «Процент вознаграждения», по умолчанию 20%).
- **Выплаты — вручную.** Автовыплат нет (вынесено за рамки MVP). Как отметить выплату — см. §12.

> Два нюанса, о которых нужно знать заранее (подробно в §13): **пароль партнёра** пока задаётся не из админки, а **счётчик «Клики»** в кабинете партнёра не растёт.

## 8. Промокоды

Создаются в **Продажи → Промокоды**. Поля:

- **Тип скидки:** процент (%) или фиксированная сумма (₽).
- **Действует до** — дата (пусто = бессрочно).
- **Лимит использований** — сколько раз можно применить (0 = без лимита).
- **Применяется к продуктам** — пусто = ко всем; иначе только к выбранным.
- **Привязан к партнёру** — засчитывать покупки с этим кодом партнёру.

Как это работает:
- На чекауте код проверяется вживую (`GET /api/promo/validate`) — покупатель сразу видит, валиден ли он.
- Итоговая цена не может опуститься ниже **1 ₽**.
- Счётчик «Использований» растёт **только после оплаты**, а не при вводе кода.
- Код сравнивается в ВЕРХНЕМ регистре — заводите коды заглавными латинскими буквами/цифрами (например `FABULA20`).

## 9. Возвраты

Оформляются **одним действием**: в нужном «Заказе» смените статус на **Возвращён**. Дальше система сама:
- вызовет ЮKassa Refund API и вернёт деньги покупателю;
- проставит дату возврата;
- аннулирует партнёрское начисление по этому заказу и уменьшит баланс/статистику партнёра.

> Возврат необратим. Убедитесь, что возвращаете правильный заказ. Если платёж по каким-то причинам не привязан (нет `ID платежа ЮKassa`), деньги через API не вернутся — тогда возврат делается в кабинете ЮKassa вручную.

## 10. Хранилище аудио и защита файлов

Платные треки лежат в **приватном** бакете Yandex Object Storage — прямой ссылкой их не скачать.

- **Демо** (короткий фрагмент) — публичное, играет прямо на сайте.
- **Полный трек** — приватный. Наружу отдаётся только **подписанная ссылка**, которая сама протухает через **1 час** (`YOS_SIGNED_URL_TTL`). Даже если ссылку кто-то перешлёт, через час она перестанет работать; в кабинете покупатель просто получит свежую.
- **Два способа привязать полный трек к продукту:**
  1. Загрузить файл в поле **«Полный аудиофайл»** продукта — файл уйдёт в приватный бакет, а путь (`fullAudioKey`) проставится сам. **Рекомендуемый способ** — консоль Yandex вам не нужна.
  2. Вписать путь вручную в поле **«Ключ в Object Storage»** (например `audio/forest-breath.m4a`), если файл уже лежит в бакете.
- Если ключей `YOS_*` в настройках нет (локальная разработка) — файлы хранятся на диске, подписанные ссылки не используются. На проде `YOS_*` обязателен.

## 11. Оплата ЮKassa — как устроено технически

- **Создание платежа:** сумма, описание (обрезается до 128 символов), `return_url` на `/success`, чек 54-ФЗ (email покупателя, позиция «услуга», `vat_code: 1` — НДС не облагается), `capture: true` (деньги списываются сразу).
- **Идемпотентность:** ключ = ID заказа (для возврата — `refund-<ID>`), поэтому повторные вызовы безопасны.
- **Проверка webhook:** тело уведомления **не считается доверенным** — сервер сам перезапрашивает платёж по его ID и сверяет статус/сумму. Так подделать оплату нельзя.
- **События:** `payment.succeeded` → выдача доступа; `payment.canceled` → заказ в «Отменён».
- **Неизвестный платёж:** если по ID платежа заказ не найден, сервер отвечает `200 OK`, чтобы ЮKassa не долбила повторами.
- **Webhook-адрес для настройки в ЮKassa:** `https://fabulaone.ru/api/webhooks/yookassa`.

## 12. Что делать в разных ситуациях (пошаговый разбор)

### Добавить новую фабулу
1. **Система → Медиа:** загрузите обложку (и, если нужно, демо-фрагмент — тоже как Медиа).
2. **Каталог → Продукты → Создать:** название, `slug` (латиница-цифры-дефис, например `forest-breath`), краткое и подробное описание, цена, продолжительность.
3. Привяжите **обложку**, при желании **демо**.
4. Загрузите **полный трек** в поле «Полный аудиофайл» (уйдёт в приватный бакет).
5. Галочка **«Опубликован»** = да. Сохраните. Товар появится на витрине.

### Загрузить/заменить полный трек
Откройте продукт → поле «Полный аудиофайл» → загрузите новый файл. Путь (`fullAudioKey`) обновится сам. Старые уже выданные ссылки протухнут в течение часа.

### Клиент оплатил, но не получил письмо/доступ
1. Найдите «Заказ» по email или номеру. Посмотрите **Статус**.
2. **Статус «Оплачен»**, а письма нет → проблема с почтой (SMTP). Доступ у клиента всё равно есть: он может зайти на `/auth/login`, ввести email и получить ссылку входа, затем скачать из `/cabinet`. Проверьте настройки SMTP и папку «Спам».
3. **Статус «Ожидает оплаты»**, хотя клиент уверяет, что заплатил → откройте платёж в кабинете ЮKassa. Если он «succeeded» — обычно достаточно, чтобы клиент вернулся на страницу `/success` (автопроверка сама добьёт заказ). Если нет — проверьте, приходят ли webhook’и (адрес в настройках ЮKassa) и живы ли ключи ЮKassa.

### Заказ завис в «Ожидает оплаты»
Это нормально для брошенных корзин (человек не оплатил). Если оплата реально была — см. пункт выше. Такие заказы можно оставлять как есть; на статистику партнёров и промокодов они не влияют (начисление только после оплаты).

### Оформить возврат
«Заказ» → Статус → **Возвращён** → сохранить. Деньги вернутся через ЮKassa, партнёрское начисление аннулируется автоматически (см. §9).

### PERSONAL: выдать готовый файл клиенту
1. Дождитесь статуса **«Анкета заполнена»** и прочитайте «Ответы на анкету».
2. Сделайте аудио, загрузите его в бакет.
3. В заказе впишите путь в **«Ключ готового аудиофайла»** (`audioKey`).
4. Смените статус на **Готово** → клиенту автоматически уйдёт письмо со ссылкой на скачивание.
   (Если у клиента нет активной сессии в кабинете — см. §13, п. 4: возможно, файл надёжнее отправить вложением или дать ссылку входа.)

### Завести партнёра
1. **Партнёры → Партнёры → Создать:** имя, email, **реф-код** (латиница/цифры, уникальный), **процент**, «Активен» = да.
2. Дайте партнёру ссылку `https://fabulaone.ru/?ref=ЕГО_КОД`.
3. **Чтобы партнёр смог войти в кабинет**, ему нужен пароль. Установка пароля пока не сделана из админки (см. §13, п. 3) — на этом шаге потребуется разработчик: он сгенерирует хэш пароля и запишет его партнёру. После этого партнёр входит на `/partner/login`.

### Отметить выплату партнёру
Автовыплат нет. После того как перевели деньги вне сайта:
1. В «Партнёре» уменьшите «Текущий баланс» на выплаченную сумму и увеличьте «Выплачено».
2. При желании в «Начислениях» переведите соответствующие строки в статус **Выплачено** и проставьте дату — для истории.

### Создать промокод
**Продажи → Промокоды → Создать:** код ЗАГЛАВНЫМИ (например `FABULA20`), тип (% или ₽), размер, при необходимости срок, лимит, список продуктов и привязку к партнёру. «Активен» = да.

### Изменить цену или тексты фабулы
Откройте «Продукт», поменяйте нужные поля, сохраните. На уже оплаченные заказы это не влияет — там сумма зафиксирована.

### Обновить юридические страницы
**Контент → Страницы.** Нужные `slug`: `offer` (оферта), `privacy` (политика), `consent` (согласие), `payment-refund` (оплата и возврат), `contacts` (контакты + реквизиты ИП). Меняете содержимое — оно сразу на сайте.

### В кабинете у покупателя «Файл временно недоступен»
Значит, у продукта не привязан полный трек или файл недоступен в бакете. Откройте «Продукт» и убедитесь, что заполнено «Полный аудиофайл» или «Ключ в Object Storage», а ключи `YOS_*` на сервере рабочие.

### Демо не проигрывается на сайте
Плеер отрисовывается, только если у продукта есть **демо**. Если демо не залито — плеер не появится. Загрузите демо-фрагмент в Медиа и привяжите к продукту.

### Проверить, что сервер жив
Откройте `https://fabulaone.ru/api/health` — должен вернуться `{"ok":true,...}`. Это удобно для мониторинга.

## 13. Известные ограничения и на что обратить внимание

Честный список мест, которые стоит держать в голове (по коду на 25.09.2026). Ни одно из них не ломает оплату/выдачу обычной фабулы — это про смежные сценарии.

1. **Счётчик «Клики» у партнёра всегда 0.** Переход по `?ref=` сохраняет cookie и корректно привязывает заказ, но поле «Переходов» нигде не увеличивается. То есть атрибуция и начисления работают, а метрика кликов — нет. Ориентируйтесь на «Оплаченных заказов» и «Сумму продаж».

2. **Автопроверка оплаты для PERSONAL не срабатывает.** Ссылка возврата ведёт на `/success?...&type=personal`, а фоновая автопроверка ждёт параметр `personal=1`. Из-за этого для PERSONAL «подстраховка» на странице успеха не отрабатывает. **На практике это некритично:** webhook от ЮKassa доводит персональный заказ до «Оплачен, ожидает анкеты» штатно. Стоит поправить при доработке.

3. **Пароль партнёра не задаётся из админки.** Поле с хэшем пароля скрыто, а формы регистрации/установки пароля нет. Пока, чтобы включить партнёру вход в кабинет, нужен разработчик (сгенерировать хэш и записать в БД). Сами реф-ссылки и начисления при этом работают без всякого пароля.

4. **Персональные заказы не видны в `/cabinet`, а письмо о готовности требует активной сессии.** Кабинет показывает только обычные заказы. Ссылка «Скачать» из письма о готовности PERSONAL открывается, только если у покупателя уже есть вход в кабинет (cookie-сессия). Надёжный обходной путь сейчас: приложить файл к письму вручную или сначала отправить клиенту «ссылку входа». (Технически маршрут `/api/personal-download` умеет принимать разовый токен — его стоит добавить в письмо при доработке.)

5. **`demoAudio` пустое → плеера нет.** Косметически плеер готов, но без залитого демо он не отображается.

6. **`PAYLOAD_PUSH=true` — только на первый деплой.** Эта настройка синхронизирует схему БД. После первого успешного старта её выключают (`false`), иначе есть риск непреднамеренных изменений схемы.

## 14. Настройки окружения (файл `.env` на сервере)

Все секреты и адреса задаются в `.env`. Ключевые:

| Переменная | Что это |
|-----------|---------|
| `DATABASE_URI`, `POSTGRES_PASSWORD` | Подключение к базе |
| `PAYLOAD_SECRET` | Секрет админки (длинная случайная строка) |
| `PAYLOAD_PUSH` | `true` только на первый деплой, потом `false` |
| `REDIS_URL` | Адрес Redis |
| `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` | Доступы ЮKassa |
| `YOOKASSA_TEST_MODE` | Тестовый режим оплаты |
| `YOS_*` (endpoint, region, bucket, ключи) | Yandex Object Storage |
| `YOS_SIGNED_URL_TTL` | Срок жизни ссылки на скачивание (сек, по умолч. 3600) |
| `NEXT_PUBLIC_SITE_URL`, `SITE_URL` | Адрес сайта (для ссылок и webhook) |
| `SMTP_*`, `EMAIL_FROM`, `EMAIL_FROM_NAME` | Почта |
| `ADMIN_EMAIL` | Куда слать «Новый заказ» |
| `MAGIC_LINK_SECRET` | Секрет ссылок входа (отдельно от Payload) |
| `AFFILIATE_WINDOW_DAYS` | Окно партнёрской атрибуции (по умолч. 30) |
| `PERSONAL_PRICE` | Цена PERSONAL в рублях (по умолч. 9900) |
| `NEXT_PUBLIC_YM_ID` | Счётчик Яндекс Метрики (пусто = выключена) |

> `.env` содержит секреты — не коммитьте его в git и не пересылайте в открытом виде.

## 15. Эксплуатация и деплой

**Запуск на сервере** — через Docker Compose (`app`, `postgres`, `redis`, `nginx`):
```bash
docker compose up -d
```
- Домены `fabulaone.ru` и `www.fabulaone.ru` должны указывать на IP сервера (A-записи). `www` автоматически редиректит на основной домен.
- HTTPS выпускается через certbot (Let’s Encrypt) — команда есть в `DEPLOY.md`.

**Резервные копии (важно):**
- База PostgreSQL — регулярный `pg_dump` (в ней заказы, клиенты, партнёры).
- Бакет Object Storage — там аудиофайлы; настройте бэкап/версионирование на стороне Yandex.

**Обновление кода:** пересобрать образ `app` и перезапустить контейнер (`docker compose up -d --build app`).

### Чеклист перед приёмкой / запуском
- [ ] `.env` заполнен на сервере (БД, `PAYLOAD_SECRET`, `MAGIC_LINK_SECRET`, `YOS_*`, ЮKassa, SMTP).

- [ ] Заведены 6 фабул: тексты, цены, обложки, демо, полные треки, «Опубликован».
- [ ] Заполнены юр. страницы: `offer`, `privacy`, `consent`, `payment-refund`, `contacts` (с реквизитами ИП).
- [ ] В ЮKassa указан webhook `https://fabulaone.ru/api/webhooks/yookassa`, `YOOKASSA_TEST_MODE=false` для боя.
- [ ] Проверена тестовая покупка: оплата → письмо → скачивание → запись в «Заказах».
- [ ] Настроен счётчик Метрики (`NEXT_PUBLIC_YM_ID`), проверена цель «покупка».
- [ ] Настроены бэкапы БД и бакета.

## 16. Безопасность и персональные данные (152-ФЗ)

- **HTTPS** обязателен; `www` редиректит на основной домен (одна сессия на оба хоста).
- **Аудио в приватном бакете** — только подписанные ссылки на 1 час, прямого доступа нет.
- **Роли:** админка — только для администратора; данные партнёров/клиентов не отдаются через публичный API (партнёрский кабинет ходит по отдельному защищённому маршруту, хэш пароля наружу не отдаётся).
- **Согласия:** при каждой покупке фиксируются факт принятия оферты и согласия на обработку ПД, дата и IP.
- **Хранение в РФ:** база и файлы — на российской инфраструктуре (VPS + Yandex Cloud).
- **Удаление данных:** у «Клиента» есть флаг «Запрошено удаление данных». Сейчас это пометка для ручной обработки запроса — по нему администратор удаляет/обезличивает данные вручную.
- **Секреты** (`PAYLOAD_SECRET`, `MAGIC_LINK_SECRET`, ключи ЮKassa и YOS) — длинные случайные строки, хранятся только в `.env` на сервере.
